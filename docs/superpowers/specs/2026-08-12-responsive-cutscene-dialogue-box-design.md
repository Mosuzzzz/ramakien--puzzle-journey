# กรอบบทพูด Cutscene ปรับขนาดตามประโยค

## เป้าหมาย

ปรับกรอบบทพูดของ Cutscene ใน Chapter 2–9 ให้ลดหรือขยายทั้งความกว้างและความสูงตามประโยคปัจจุบัน วางกึ่งกลางด้านล่าง และแสดงข้อความ `กด E เพื่อดำเนินเรื่องต่อ ▼` ภายในกรอบแบบ Chapter 1 โดยไม่ซ้อนกับขอบกรอบ

## สาเหตุของปัญหาปัจจุบัน

`CutsceneDialoguePresenter` ใช้กรอบที่กว้างเกือบเต็มหน้าจอและสูงคงที่ทุกประโยค ขณะที่ `ContinuePrompt` ของแต่ละ Chapter เป็น Label แยกซึ่งวางทับบริเวณขอบล่างของกรอบ จึงเกิดทั้งพื้นที่ว่างเกินจำเป็นและข้อความกด E ซ้อนกับลายกรอบ

## พฤติกรรมที่ผู้เล่นจะเห็น

- กรอบบทพูดอยู่กึ่งกลางด้านล่างของหน้าจอ
- ประโยคสั้นใช้กรอบที่แคบและเตี้ยลง
- ประโยคยาวขยายกรอบจนถึงความกว้างสูงสุด จากนั้นตัดบรรทัดอย่างเป็นระเบียบและเพิ่มความสูงตามจำนวนบรรทัด
- ป้ายชื่อผู้พูดอยู่กึ่งกลางเหนือกรอบและเคลื่อนตามกรอบ
- ข้อความ `กด E เพื่อดำเนินเรื่องต่อ ▼` อยู่ภายในกรอบ ชิดขวา และมีพื้นที่แยกจากข้อความบทพูดเหมือน Chapter 1
- กรอบมีขนาดขั้นต่ำเพื่อรักษาลาย NinePatch ป้ายชื่อ และพื้นที่ข้อความกด E และมีขนาดสูงสุดเพื่อไม่ให้ล้น viewport
- คำบรรยายที่ไม่มีชื่อผู้พูดยังคงใช้รูปแบบเต็มจอเดิม และไม่แสดงกรอบบทพูด

## การออกแบบระบบ

แก้ที่ `scenes/ui/cutscene_dialogue_presenter` เพียงจุดเดียว เนื่องจาก Cutscene ที่เกี่ยวข้องทุก Chapter ใช้ presenter กลางนี้อยู่แล้ว ไม่ปรับตำแหน่งแยกทีละฉาก

### การจัดวางกรอบ

- เปลี่ยน `Box` ให้ยึด anchor กึ่งกลางแนวนอนและด้านล่าง
- คำนวณขนาดจากข้อความด้วยฟอนต์จริงของ `TextLabel`
- ความกว้างที่ต้องการเท่ากับความกว้างข้อความบวกพื้นที่ขอบและ padding
- จำกัดความกว้างด้วยค่าขั้นต่ำที่รองรับลายกรอบ/ข้อความกด E และค่าสูงสุดตามสัดส่วน viewport เดิม
- เมื่อข้อความกว้างเกินค่าสูงสุด ให้เปิด word-smart wrapping แล้วคำนวณความสูงจากจำนวนบรรทัดจริง
- ความสูงเท่ากับความสูงข้อความที่ wrap แล้ว บวกพื้นที่ด้านบน พื้นที่ prompt และ padding ด้านล่าง
- คำนวณใหม่เมื่อเปลี่ยนประโยคหรือเมื่อขนาด viewport เปลี่ยน

### ข้อความกด E

เพิ่ม `ContinueLabel` ภายใน presenter และวางใต้ข้อความบทพูดโดยชิดขวาแบบ Chapter 1 เมื่อแสดงบทพูด presenter จะคัดลอกข้อความจาก `ContinuePrompt` เดิมมาแสดงใน `ContinueLabel` และซ่อน Label ภายนอก จึงรักษาข้อความแบบ dynamic เช่นคำสั่งจบ Cutscene ได้โดยไม่ต้องเปลี่ยน story flow ของแต่ละ Chapter

เมื่อแสดงคำบรรยาย presenter จะซ่อน `ContinueLabel` และใช้ `ContinuePrompt` ภายนอกตามรูปแบบเดิม เพราะโหมดนี้ไม่มีกล่องบทพูด

### ความเข้ากันได้

- API `show_line(line, prompt_label)` เดิมยังใช้ได้
- สคริปต์ Cutscene ยังคงเป็นเจ้าของ input, การเปลี่ยนข้อความ prompt, fade, skip และลำดับเนื้อเรื่อง
- presenter รับผิดชอบเฉพาะการนำเสนอและการจัดขนาด
- ไม่เปลี่ยนระบบบทสนทนา Chapter 1

## ทางเลือกที่พิจารณา

1. **คำนวณขนาดใน presenter กลาง — เลือกใช้:** ได้ขนาดตรงกับฟอนต์และข้อความจริง แก้ทุก Chapter พร้อมกัน และรองรับ viewport หลายขนาด
2. **กำหนดขนาดเล็ก/กลาง/ใหญ่จากจำนวนตัวอักษร:** ทำง่ายกว่า แต่ความกว้างตัวอักษรไทยไม่เท่ากันและคาดการณ์การ wrap ได้ไม่แม่นยำ
3. **ปรับ scene ทีละ Chapter:** เพิ่มความซ้ำซ้อนและเสี่ยงให้หน้าตาแต่ละ Chapter ไม่ตรงกัน

## การทดสอบ

- เพิ่ม runtime test เปรียบเทียบประโยคสั้นและยาว โดยกรอบประโยคสั้นต้องแคบและเตี้ยกว่า
- ตรวจว่าประโยคยาวไม่เกินความกว้างสูงสุดและเพิ่มความสูงเมื่อเกิดการ wrap
- ตรวจว่า Box อยู่กึ่งกลางด้านล่างหลังเปลี่ยน viewport
- ตรวจว่า `ContinueLabel` อยู่ภายในขอบ Box และไม่ชนขอบล่าง
- ตรวจว่า prompt ภายนอกถูกซ่อนในโหมดบทพูด แต่ยังแสดงในโหมดคำบรรยาย
- รัน integration test ที่ตรวจ presenter ใน Cutscene ทุก Chapter
- ตรวจภาพประโยคสั้นและยาวที่ 1920×1080 และ viewport ที่แคบกว่า
- รันชุดทดสอบ Cutscene เดิมและโหลดโปรเจกต์แบบ headless เพื่อป้องกัน regression

## สิ่งที่ไม่เปลี่ยน

- เนื้อหา ชื่อผู้พูด และลำดับประโยค
- การกด E คลิกซ้าย ปุ่มข้าม fade และ animation
- เงื่อนไขจบ Cutscene ระบบเควส และการเปลี่ยนฉาก
- รูปแบบคำบรรยายที่ไม่มีกล่องบทพูด
